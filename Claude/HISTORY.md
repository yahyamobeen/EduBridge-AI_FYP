- 2026-10-13 — Phase 2 of the ColQwen2 tutor work: **the retrieval service**, at `ml/serving/` — the first real tenant of a directory that had held a `.gitkeep` since August, and the first code in this project that actually loads ColQwen2. A separate deployable: its own `requirements.txt`, `Dockerfile`, ruff config and self-test, never imported by `backend/`, because the model needs ~5 GB resident at bfloat16 and the backend runs on a 512 MB instance. `POST /retrieve` → `{pages, scores, encode_ms, search_ms, cached, checkpoint}`; `GET /health` reports readiness, checkpoint and cache hit rate, and needs no credential because a health check that needs one is a health check the platform cannot use. **The three startup guards from `bench.py` are carried over and they `SystemExit`** — all of them before the ~5 GB load, so a mispaired file fails in seconds rather than after a two-minute load: checkpoint equality (⚠️ the important one — a ColQwen2 query scored against ColPali pages yields confidently wrong citations with no error anywhere, both being 128-dimensional), pages exactly 1–200, and a pages/embeddings length match. Unlike the backend, this process does **not** degrade: it has one job and must not accept traffic it cannot do correctly. **Two design properties are load-bearing rather than incidental.** First, **a cache hit never touches the model lock** — the page embeddings are read-only after startup, so cached queries run MaxSim concurrently while a novel query holds the encoder; with one serialised model that is what stops a repeated question queueing behind a new one, and it is why `tdd.md:759`'s cache, not the model's raw speed, is what satisfies NFR-1. There is also a re-check inside the lock, so a burst of identical questions — which is what a classroom produces — does not each pay full price. Second, **`MAX_WAIT_S` (15 s) must stay below the backend's 20 s read timeout**, or the caller abandons the request before the service can answer "busy" and degrades on a transport error instead, losing the distinction between *overloaded* and *unreachable*. - 2026-10-13 — Phase 5 of the ColQwen2 tutor work: **turn routing.** The anchor half of this phase landed with Phases 1-3 (the `chapter` column, the prior applied in all three tiers); this is the other half, and it rests on an observation the contract already made and nothing implemented: **most turns in a tutoring conversation are not retrieval turns.** New `app/tutor/turns.py` classifies each turn as `reference`, `followup` or `retrieve` before any retrieval runs — no database, no model, no settings, the same discipline as `gate.py` and `onboarding.py`, so every rule is testable without a connection string. **`reference`** fires on a kind word followed by a number — `prd.md` FR-1's own `chp 4 ex 4.5 q 3`, or `numerical 7.3` — and routes to the syllabus index instead of the neural tier, because MaxSim over a 150 DPI scan is particularly bad at a citation: "7.3" is a few dark pixels on a page full of them. The kind word is REQUIRED, which is what keeps "convert 30 degrees celsius to fahrenheit" out; a bare number is not a reference and most numbers a student types are physics. **`followup`** fires on a short, topicless turn carrying a follow-up marker and **skips retrieval entirely**, reusing the previous answer's cited pages via the new `last_turn_pages`. That is not only cheaper, it is more correct: re-retrieving on "explain that again" can return a DIFFERENT page set, and the tutor then explains something adjacent to what the student is looking at and appears to contradict itself. ⚠️ **The bias is deliberately asymmetric and that is the part to preserve.** A missed follow-up costs a few seconds nobody needed; a FALSE follow-up answers a new question from the previous question's pages, which is a confidently wrong answer. Three guards all fall back to `retrieve`: naming any term the syllabus index recognises, exceeding eight words, or carrying no recognised marker. The topic guard tests against the index's **own vocabulary** (`TOPIC_TERMS`, built from `EVALSET_ANCHORS` and `SUBTOPIC_INDEX`) rather than a hand-written stopword list, so the two cannot drift — a separate list would, and the drift would surface as follow-ups being misread. ⚠️ **Two bugs found by smoke-testing the classifier before writing its tests, both now covered.** (1) `"why?"` — the commonest follow-up a student types — classified as `retrieve`, because the markers held "why is that" but not the bare form; bare interrogatives in all three languages are now recognised, but only when the turn is three words or fewer, so "why is the sky blue" stays a new question. (2) `"explain thermocouples again"` classified as `followup` — the index holds the singular and an exact word-set intersection missed the plural. **That failed in the dangerous direction**, so plurals are now matched both ways (a trailing `s` only — a general prefix match would find "heat" inside "heather"). ⚠️ **`retriever` and `intent` are now reported SEPARATELY** on the `pages` event and the chat response, and both are required: `heuristic`+`reference` is a correct exercise lookup while `heuristic`+`retrieve` is a degraded answer from an unreachable retrieval service, and with one field a client must either alarm on both or neither. `retrieve_for_turn` is the single place both the streaming and non-streaming handlers route through, so the two cannot disagree about a turn's kind — which would show up as the same question answered from different pages depending on which route the client called. **356 unit tests pass** (304 before); 52 new, with the ones that matter most asserting the fallback direction rather than the happy path — docs updated: `tdd.md`, `Claude/HISTORY.md` — Claude
