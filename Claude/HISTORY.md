- 2026-10-13 — Phase 2 of the ColQwen2 tutor work: **the retrieval service**, at `ml/serving/` — the first real tenant of a directory that had held a `.gitkeep` since August, and the first code in this project that actually loads ColQwen2. A separate deployable: its own `requirements.txt`, `Dockerfile`, ruff config and self-test, never imported by `backend/`, because the model needs ~5 GB resident at bfloat16 and the backend runs on a 512 MB instance. `POST /retrieve` → `{pages, scores, encode_ms, search_ms, cached, checkpoint}`; `GET /health` reports readiness, checkpoint and cache hit rate, and needs no credential because a health check that needs one is a health check the platform cannot use. **The three startup guards from `bench.py` are carried over and they `SystemExit`** — all of them before the ~5 GB load, so a mispaired file fails in seconds rather than after a two-minute load: checkpoint equality (⚠️ the important one — a ColQwen2 query scored against ColPali pages yields confidently wrong citations with no error anywhere, both being 128-dimensional), pages exactly 1–200, and a pages/embeddings length match. Unlike the backend, this process does **not** degrade: it has one job and must not accept traffic it cannot do correctly. **Two design properties are load-bearing rather than incidental.** First, **a cache hit never touches the model lock** — the page embeddings are read-only after startup, so cached queries run MaxSim concurrently while a novel query holds the encoder; with one serialised model that is what stops a repeated question queueing behind a new one, and it is why `tdd.md:759`'s cache, not the model's raw speed, is what satisfies NFR-1. There is also a re-check inside the lock, so a burst of identical questions — which is what a classroom produces — does not each pay full price. Second, **`MAX_WAIT_S` (15 s) must stay below the backend's 20 s read timeout**, or the caller abandons the request before the service can answer "busy" and degrades on a transport error instead, losing the distinction between *overloaded* and *unreachable*. The anchor prior is applied **before** top-k and therefore has to live in the service: the backend only ever sees the pages that already survived selection. `measure.py` produces the number this work has been waiting on — median encode cold and cached, cache hit rate, model load time, peak RSS, and **whether `amx_bf16` is present**, with instructions to A/B against `ONEDNN_MAX_CPU_ISA=AVX512_CORE_BF16` in a second process because oneDNN reads that variable once at initialisation. It states plainly that a laptop result is not the deployment number, since without AVX512-BF16 or AMX bfloat16 is a *fit* decision and measurably slower than float32. `Dockerfile` installs torch in its own layer from the CPU-only index (~200 MB rather than ~2.5 GB of unused CUDA wheels), pre-downloads the model weights at build time so a cold start has no runtime dependency on Hugging Face, runs as a non-root user and pins **one** uvicorn worker — each worker would load its own copy and exhaust memory rather than double throughput. ⚠️ The image cannot be built from a clean clone: `pages.colqwen2.pt` is gitignored and must be supplied. **`selftest.py` adds 39 checks that stub torch** and so need no model and no spare RAM, covering every guard refusal (including duplicate and out-of-range page lists), the cache key, chapter mapping, constant-time secret comparison, request validation bounds, and that `MAX_WAIT_S` is below the backend's timeout. **`tests/unit/test_retrieval_tiers.py` adds 18 backend tests** for the process boundary: a remote response is INPUT and is validated before it becomes a citation, because an out-of-range page renders as a link to a page that does not exist and is indistinguishable in the interface from the retriever being wrong.
